# 💬 익명 피드백 서비스

> ### 팀원 간 솔직한 피드백을 익명으로 주고받을 수 있는 웹 서비스
>
> **6자리 코드로 페이지 공유 → 익명 피드백 작성 → 4자리 PIN으로 본인만 확인**

---

## 📌 프로그램 한눈에 보기

| 구분 | 내용 |
|---|---|
| **서비스 목적** | 팀원 간 장점과 개선점을 부담 없이 익명으로 전달 |
| **주요 사용자** | 팀 프로젝트, 교육 과정, 스터디, 소규모 조직 |
| **피드백 방식** | 장점 / 단점 및 개선점 분리 작성 |
| **페이지 접근** | 6자리 고유 코드 |
| **본인 확인** | 4자리 PIN |
| **익명성** | 작성자 식별 정보 미수집 |
| **관리 기능** | 페이지, 피드백 조회 및 삭제, 서비스 잠금 |
| **배포 환경** | GitHub + Vercel + Supabase |

# 🎯 서비스 소개

> **왜 만들었나요?**
>
> 팀 프로젝트나 교육 과정에서는 서로에게 도움이 되는 피드백이 필요하지만,  
> 직접 이야기하기 어려운 내용은 충분히 전달되지 않는 경우가 있습니다.
>
> 이 서비스는 **작성자의 정보를 수집하지 않는 익명 피드백 환경**을 제공해  
> 구성원들이 장점과 개선점을 보다 편하게 전달할 수 있도록 만든 서비스입니다.

### 👥 이런 상황에서 사용할 수 있어요

| 활용 상황 | 활용 방법 |
|---|---|
| 👨‍👩‍👧‍👦 팀 프로젝트 | 프로젝트 종료 후 팀원 상호 피드백 |
| 🎓 교육 과정 | 수강생 간 협업 피드백 |
| 📚 스터디 | 활동 종료 후 회고 및 의견 수집 |
| 🏢 소규모 조직 | 구성원 간 장점 및 개선점 공유 |
| 🧑‍💻 협업 프로젝트 | 역할 수행 및 협업 방식 피드백 |

# ✨ 주요 기능

## 👤 01. 개인 피드백 페이지

> 이름 또는 닉네임과 4자리 PIN을 설정하면  
> **개인 전용 피드백 페이지와 6자리 코드가 자동 생성됩니다.**

| 기능 | 설명 |
|---|---|
| 이름 / 닉네임 | 페이지 소유자 정보 |
| 직무 / 역할 | 선택 입력 |
| 4자리 PIN | 본인 피드백 확인 및 페이지 삭제 시 사용 |
| 6자리 코드 | 다른 사람에게 공유하는 고유 페이지 코드 |

---

## ✍️ 02. 익명 피드백 작성

피드백 작성자는 **회원가입 없이** 바로 피드백을 남길 수 있습니다.

| ✅ 장점 | 🔧 단점 및 개선점 |
|---|---|
| 잘하고 있는 부분 | 개선하면 좋을 부분 |
| 계속 유지했으면 하는 부분 | 협업 과정에서 아쉬웠던 부분 |
| 강점으로 느껴진 부분 | 보완하면 좋을 부분 |

> 🔒 **익명 보장**
>
> 작성자의 이름, 계정 등 별도의 식별 정보를 입력받지 않으며  
> 피드백 데이터에도 작성자를 구분하는 정보가 저장되지 않습니다.

---

## 🔎 03. 페이지 검색

피드백을 작성하려는 사용자는 아래 두 가지 방법으로 상대방의 페이지를 찾을 수 있습니다.

| 검색 방식 | 설명 |
|---|---|
| 🔢 **6자리 코드 검색** | 공유받은 페이지 코드를 입력 |
| 👤 **이름 검색** | 이름 또는 닉네임으로 검색 |

검색 결과에서 대상 페이지를 선택한 후 바로 익명 피드백을 작성할 수 있습니다.

---

## 🔐 04. PIN 기반 피드백 확인

> 페이지 소유자의 피드백은 **4자리 PIN 인증 후에만 확인할 수 있습니다.**

PIN 인증이 완료되면 피드백을 다음과 같이 구분해 확인할 수 있습니다.

| 탭 | 내용 |
|---|---|
| ✅ 장점 | 받은 장점 피드백 모아보기 |
| 🔧 단점 | 받은 개선점 피드백 모아보기 |

---

## ⚡ 05. 내 페이지 바로가기

6자리 페이지 코드를 알고 있다면 홈 화면에서 바로 본인의 페이지로 이동할 수 있습니다.

```text
6자리 코드 입력
      ↓
PIN 인증
      ↓
내 피드백 확인
````

> 💡 `내가 만든 페이지` 목록이 보이지 않아도
> **코드만 알고 있다면 바로 접근할 수 있습니다.**

---

## ♻️ 06. 내 페이지 복구

브라우저 변경이나 저장 데이터 초기화로
`내가 만든 페이지` 목록이 사라진 경우 다시 복구할 수 있습니다.

| 필요한 정보  | 용도         |
| ------- | ---------- |
| 6자리 코드  | 복구할 페이지 확인 |
| 4자리 PIN | 페이지 소유자 인증 |

```text
페이지 코드 입력
      ↓
PIN 입력
      ↓
인증 확인
      ↓
내 페이지 목록에 다시 등록
```

---

## 🔔 07. 새 피드백 알림

마지막으로 피드백을 확인한 이후
새롭게 등록된 피드백이 있는지 자동으로 확인합니다.

> ### 👀 3개의 새로운 피드백이 있어요!

새 피드백이 있는 경우 화면 하단에 알림이 나타나며,
피드백 확인 시점을 기준으로 새로운 피드백 카운트가 갱신됩니다.

# 🛡 관리자 기능

## 📊 관리자 대시보드

관리자 페이지에서는 서비스 전체 현황을 한눈에 확인할 수 있습니다.

| 관리 항목     | 기능                 |
| --------- | ------------------ |
| 📄 전체 페이지 | 생성된 전체 페이지 수 확인    |
| 💬 전체 피드백 | 등록된 전체 피드백 수 확인    |
| 👥 페이지 목록 | 생성된 모든 페이지 조회      |
| 🔍 상세 조회  | 페이지별 피드백 내용 확인     |
| 🗑 개별 삭제  | 특정 피드백만 선택하여 삭제    |
| ❌ 페이지 삭제  | 페이지와 연결된 피드백 전체 삭제 |
| 🔒 서비스 잠금 | 신규 생성 및 작성 차단      |

---

## 🔒 서비스 OPEN / CLOSED

관리자는 서비스 운영 상태를 직접 변경할 수 있습니다.

| 기능        | 🟢 OPEN | 🔴 CLOSED |
| --------- | :-----: | :-------: |
| 신규 페이지 생성 |    ✅    |     ❌     |
| 신규 피드백 작성 |    ✅    |     ❌     |
| 기존 페이지 조회 |    ✅    |     ✅     |
| 기존 피드백 확인 |    ✅    |     ✅     |

> **CLOSED 상태는 읽기 전용 모드입니다.**
>
> 기존 데이터는 유지하면서 신규 페이지 생성과 피드백 작성만 차단할 수 있습니다.

# 🕶 익명성 처리

> ### 작성자가 누구인지 확인할 수 없도록 설계했습니다.

`feedbacks` 데이터에는 작성자를 특정하기 위한 별도 컬럼이 존재하지 않습니다.

| 저장되는 정보   | 저장 여부 |
| --------- | :---: |
| 작성자 이름    |   ❌   |
| 작성자 계정    |   ❌   |
| 작성자 닉네임   |   ❌   |
| 장점 내용     |   ✅   |
| 단점 내용     |   ✅   |
| 작성 시각     |   ✅   |
| 대상 페이지 코드 |   ✅   |

따라서 페이지 소유자는 **피드백 내용은 확인할 수 있지만 작성자는 확인할 수 없습니다.**

# 🗃 Database

## `pages`

개인 피드백 페이지 정보를 관리합니다.

| Column       | Description   |
| ------------ | ------------- |
| `code`       | 6자리 고유 페이지 코드 |
| `name`       | 이름 또는 닉네임     |
| `role`       | 직무 및 역할       |
| `pin`        | 4자리 PIN       |
| `created_at` | 페이지 생성 시각     |

## `feedbacks`

페이지별 피드백 정보를 관리합니다.

| Column       | Description   |
| ------------ | ------------- |
| `id`         | 피드백 고유 ID     |
| `page_code`  | 피드백 대상 페이지 코드 |
| `strength`   | 장점 피드백        |
| `weakness`   | 단점 및 개선점 피드백  |
| `created_at` | 피드백 작성 시각     |
